# Internacionalización (i18n)

Tamborradata está disponible en **español (`es`, por defecto), inglés (`en`) y euskera (`eu`)** con **next-intl 4**. El español es la fuente de verdad de los textos y el sistema de tipos obliga a que `en` y `eu` tengan exactamente las mismas claves.

## Enrutado

```typescript
// i18n/routing.ts
export const routing = defineRouting({
  locales: Object.values(locale),
  defaultLocale: locale.es,
  localePrefix: 'as-needed',
  localeDetection: false,
  alternateLinks: false,
});
```

| Opción                  | Efecto                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------- |
| `localePrefix: 'as-needed'` | El idioma por defecto no lleva prefijo (`/statistics/...`); los demás sí (`/en/...`, `/eu/...`) |
| `localeDetection: false`    | No se redirige según `Accept-Language` ni cookie: la URL manda                          |
| `alternateLinks: false`     | next-intl no emite cabeceras `Link` de alternativas; los `hreflang` se generan en `i18n/seo.ts` |

`proxy.ts` aplica el middleware de next-intl a todo salvo `/api`, `_next`, `_vercel` y archivos con extensión.

Los helpers de navegación (`Link`, `redirect`, `permanentRedirect`, `usePathname`, `useRouter`, `getPathname`) se importan siempre de `i18n/navigation.ts`, no de `next/navigation`, para conservar el prefijo de idioma.

### Cómo se resuelve el idioma

`i18n/request.ts` lee el parámetro de ruta `[locale]` con `next/root-params`, cae al idioma por defecto si no es válido y carga el bundle completo:

```typescript
const requested = await rootLocale();
const locale = hasLocale(routing.locales, requested) ? requested : routing.defaultLocale;
const messages = (await import(`./translations/${locale}`)).default;
```

`[locale]/layout.tsx` llama a `notFound()` si el segmento no es un idioma válido, genera un `generateStaticParams` por idioma y asigna `<html lang={locale}>`. `app/not-found.tsx` queda fuera de `[locale]`: usa `getLocale()` y su propio `NextIntlClientProvider`.

## Estructura de traducciones

Un archivo por namespace y por idioma:

```
i18n/translations/
├── es/   ← fuente de verdad
│   ├── index.ts
│   ├── errorPage.ts   footer.ts   header.ts   landing.ts
│   ├── notFound.ts    policy-privacy.ts   search.ts
│   └── site.ts        statistics.ts
├── en/   (mismos archivos)
└── eu/   (mismos archivos)
```

`index.ts` agrupa los namespaces, con las mismas claves en los tres idiomas:

| Namespace       | Clave en `index.ts` |
| --------------- | ------------------- |
| `errorPage.ts`  | `ErrorPage`         |
| `footer.ts`     | `Footer`            |
| `header.ts`     | `Header`            |
| `landing.ts`    | `Landing`           |
| `notFound.ts`   | `NotFound`          |
| `policy-privacy.ts` | `PrivacyPolicy` |
| `search.ts`     | `Search`            |
| `site.ts`       | `Site`              |
| `statistics.ts` | `Statistics`        |

### `es` define, `en` y `eu` verifican

```typescript
// es/footer.ts
const footer = {
  openSource: 'Código abierto en GitHub',
  policyPrivacy: 'Política de privacidad',
  copyright: '© {year} Tamborradata - Todos los derechos reservados.',
};
export default footer;

// en/footer.ts
import type footer from '../es/footer';

export default {
  openSource: 'Open source on GitHub',
  policyPrivacy: 'Privacy policy',
  copyright: '© {year} Tamborradata - All rights reserved.',
} satisfies typeof footer;
```

Si falta una clave, sobra una o cambia la forma en `en`/`eu`, `tsc` falla. Los parámetros ICU (`{year}`, `{period}`) viven dentro del texto.

## Tipado: `Messages`

```typescript
// i18n/types.ts
export type Messages = typeof es;

declare module 'next-intl' {
  interface AppConfig {
    Locale: Locale;
    Messages: Messages;
  }
}
```

Con esta augmentación, `useTranslations('Landing.metadata')` y `t('title')` se comprueban en compilación: namespaces y claves inexistentes son error de tipos.

## Uso en componentes

| Contexto                        | API                                                        |
| ------------------------------- | ---------------------------------------------------------- |
| Server Component async / `generateMetadata` | `await getTranslations('Namespace')`, `await getLocale()`, `await getFormatter()` de `next-intl/server` |
| Componente (servidor o cliente) | `useTranslations('Namespace')`, `useLocale()` de `next-intl` |
| Texto con marcado               | `t.rich('clave', { ... })` (política de privacidad, hero del buscador) |

```typescript
const t = useTranslations('Landing.buyMeACoffee');
// ...
<h2>{t('title')}</h2>
```

`NextIntlClientProvider` se monta en `[locale]/layout.tsx` (sin props: hereda locale y mensajes de `request.ts`), así que los componentes cliente pueden usar `useTranslations` directamente.

### Constructores de textos compartidos

Cuando el mismo texto se usa en metadatos y en datos estructurados, se centraliza en una función que recibe el traductor ya acotado, por ejemplo `buildLandingTexts(t, overview)`. Su tipo se declara con `ReturnType<typeof useTranslations<'Landing.metadata'>>` y sirve tanto para `useTranslations` como para `getTranslations`.

## Cambio de idioma

`LanguageSwitcher` (cabecera) pinta tres botones `ES / EN / EU` y delega en `useChangeLocale`:

```typescript
function changeLocale(nextLocale: Locale) {
  if (nextLocale === locale) return;
  const { search, hash } = window.location;

  startTransition(() => {
    router.replace(`${pathname}${search}${hash}`, { locale: nextLocale, scroll: false });
  });
}
```

- Mantiene ruta, query y hash, y no hace scroll.
- Usa `useTransition`: `isPending` deshabilita los botones y atenúa el control.
- Lee `window.location` al hacer clic para no requerir un `Suspense` (lo exigiría `useSearchParams`).
- Cada botón lleva `lang`, `aria-label` con el nombre del idioma y `aria-current` en el activo.

## Textos pequeños en línea

Para cadenas mínimas y estables que no justifican un namespace, el componente define un mapa tipado por idioma. Ejemplo real, `components/ui/BuyMeACoffee.tsx`:

```typescript
const TEXT: Record<Locale, { cta: string; newTab: string }> = {
  es: { cta: 'Invítame a un café', newTab: '(se abre en una pestaña nueva)' },
  en: { cta: 'Invite me for a coffee', newTab: '(opens in a new tab)' },
  eu: { cta: 'Gonbida nazazu kafe batera', newTab: '(fitxa berri batean irekitzen da)' },
};

const { cta, newTab } = TEXT[useLocale()];
```

`Record<Locale, ...>` garantiza que no falte ningún idioma. Si el texto crece o se reutiliza, muévelo a un namespace.

## Formato de números

`useNumberFormatter` (`i18n/useNumberFormatter.ts`) devuelve un `Intl.NumberFormat` con el mismo resultado en servidor y cliente:

- El euskera se formatea como español (`NUMBER_LOCALE`): mismos separadores, y algunos navegadores no traen datos `Intl` de `eu`, lo que provocaría un error de hidratación.
- `useGrouping: 'always'` para que los números de 4 cifras lleven separador.
- Los formateadores se cachean por idioma y opciones.

## SEO e idiomas alternativos

`i18n/seo.ts` genera, a partir de la ruta sin prefijo:

| Función                     | Resultado                                                                     |
| --------------------------- | ----------------------------------------------------------------------------- |
| `getAlternates(locale, href)` | `canonical` + `languages` con los tres idiomas y `x-default` (idioma por defecto) |
| `getOpenGraphLocales(locale)` | `og:locale` (`es_ES`, `eu_ES`, `en_US`) y `alternateLocale` con los otros dos |
| `getLanguageTag(locale)`    | Etiqueta BCP 47 (`es-ES`...) para `inLanguage` en JSON-LD                     |

Las URLs se construyen con `getPathname`, así que respetan `as-needed`. Más contexto en [seo.md](./seo.md).

## Cómo añadir un namespace

1. Crea `translations/es/miSeccion.ts` con `const miSeccion = { ... }; export default miSeccion;`.
2. Crea `translations/en/miSeccion.ts` y `translations/eu/miSeccion.ts` con `import type miSeccion from '../es/miSeccion';` y `export default { ... } satisfies typeof miSeccion;`.
3. Registra el namespace en los **tres** `index.ts` con la misma clave (`MiSeccion`).
4. Úsalo con `useTranslations('MiSeccion')` o `getTranslations('MiSeccion')`.
5. Ejecuta `tsc` para confirmar que `en` y `eu` encajan con `es`.

## Cómo añadir un idioma

1. Añade el código en `app/types/locale.ts`; `routing.locales` se deriva de ese objeto.
2. Copia `translations/es/` a `translations/<nuevo>/` y traduce cada archivo manteniendo `satisfies typeof ...`. `request.ts` importa `./translations/${locale}`, así que no requiere más cambios.
3. Completa los `Record<Locale, ...>` que `tsc` marcará como incompletos: `openGraphLocales` en `i18n/seo.ts`, `NUMBER_LOCALE` en `i18n/useNumberFormatter.ts` y `TEXT` en `BuyMeACoffee.tsx`. La lista `languages` de `LanguageSwitcher.tsx` es un array simple: `tsc` no avisa, hay que añadir el botón a mano.
4. Actualiza los patrones de `next.config.ts` que enumeran idiomas (`/:locale(en|es|eu)/search`).
5. Revisa metadatos y datos estructurados en el nuevo idioma.

Véase también: [data-fetching.md](./data-fetching.md), [seo.md](./seo.md).
